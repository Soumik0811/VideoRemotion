# ODDLY LOGICAL — ANIMATION ENGINE V6

## Active production direction

Use V6 object-led cartoon storytelling for all new Shorts and videos. The canonical reference is [ANIMATION ENGINE.txt](ANIMATION%20ENGINE.txt). Read it when producing an episode; this master keeps the durable operating rules and resolves conflicts with older V5 material.

The goal is to borrow pacing and visual storytelling principles from the reference, never its characters, artwork, branding, or complete compositions. Oddly Logical keeps its own established identity and reusable assets.

### Visual language

- Preserve the established cast: Oliver, Leo, Maya, and Mr. Brooks. Do not redesign faces, proportions, clothing identity, or prior episode casts.
- Prefer simple, stable character movement: stand, short walks, blink, look, nod, expression changes, simple points, celebration and reactions.
- Make environments and objects carry the explanation. Animate cards, money, products, counters, mechanisms, calendars, bars, and reveals.
- Avoid realistic grabbing, handoffs, detailed hands, inverse kinematics, stretched arms, and complex limb choreography in new work. Represent transactions with clear floating/sliding objects and reactions.
- Preserve topic-matching scenery and return to recognizable locations with consistent layouts. Add only relevant ambient activity, typically a few frame-driven motions.
- Use bold, short headings and readable numerical reveals. Show calculations in steps. Use comparison layouts where they clarify two outcomes.
- Use radial-burst concept screens selectively; story-world scenes retain their real, topic-specific environments.
- Keep meaningful visual changes frequent but motivated by the narration. Reserve the largest visual payoff for the conclusion.

## Six reusable beat templates

Select and combine automatically as the narration requires; do not force a fixed order:

1. **Story World** — recognizable location, characters, props, ambient activity, motivated camera motion.
2. **Concept Reveal** — brief branded radial burst and concise concept label.
3. **Object Mechanism** — animate a process through moving, appearing, duplicating, transforming or disappearing objects.
4. **Math Reveal** — sequential values and equation, with a readable hold and emphasized result.
5. **Comparison Screen** — balanced, independently changing sides.
6. **Final Payoff** — strongest reveal, relevant reaction and minimal competing text.

Use V6 object-motion building blocks where appropriate: pop/slide, float/drop/bounce, scale reveal, duplicate/stack, path movement, morph/replace, counters, coin rain, product flow, pipeline assembly, calendar flip, progress fill, bar growth, split-screen reveal, and number impact. These are desired reusable capabilities, not a claim that every component already exists.

## Episode workflow

1. Read the complete supplied narration; preserve its wording and financial figures.
2. Inspect studio/library.json and the relevant existing episode systems before creating assets.
3. Map narration beats to the six templates, existing locations, cast, props, object actions, ambient actions, headings, camera motion and transitions.
4. Save the episode script and time-coded storyboard in a new episode location. Use audio timing when available; otherwise mark editable estimates and do not claim synchronization.
5. Implement the composition with deterministic frame-driven Remotion animation. Reuse the existing SVG and Remotion stack. Do not add dependencies or paid media generation without need/authorization.
6. Check values, identity continuity, object placement, timing, transitions, captions and representative frames across motion sequences. Render when practical and verify the output file exists before reporting it.
7. Add reusable assets to the catalog with truthful implementation status. Preserve earlier episodes and their assets.

Default delivery target is 1080×1920, 30 FPS, H.264 unless the user requests otherwise. Use licensed or original audio only; never attach an old episode's narration to a new story by default.

## Launch behavior

Treat “initiate the master prompt” and “INITIATE ODDLY LOGICAL” as equivalent, case-insensitive commands. Each launch starts a fresh episode. If its final narration is missing, request it and optionally narration audio. An older episode's script is not narration for the new episode. If the current narration is already supplied, proceed and infer routine creative decisions.

Updating these instructions alone is configuration work; it does not start an episode. Do not repeat first-time setup simply because this file is read.

## Permanent safeguards

- Use the V5 permanent cast identities for new episodes, animated under the simpler V6 motion philosophy.
- Never retroactively rename, redesign, or rewrite earlier episode characters or exports.
- Keep the finalized script and figures intact. Separate supplied claims, verified claims, and explicitly hypothetical examples.
- Prefer reusable local assets and existing tools. Paid generation remains disabled unless explicitly authorized.
- Report actual storyboard, composition, preview/render paths, reused/new assets, duration status, and remaining limitations.
